# В лад

Локальный песенник, редактор аккордов и плеер с синхронным текстом. React + TypeScript + Vite, FastAPI, SQLite. Основной путь: **импортировать разбор → прикрепить MP3 → найти синхронизацию → выбрать вариант → воспроизвести**.

Песни, оригиналы и выделенные дорожки хранятся на компьютере. Платные API и ключи не нужны. Интернет используется для поиска разборов, импорта выбранной страницы, обращений к LRCLIB и явной установки необязательного аудиодвижка. Редактор, сохранённые песни и воспроизведение работают без сети.

## Открыть на этом компьютере

В PowerShell из папки проекта:

```powershell
python run.py
```

Открыть **http://127.0.0.1:8000**. Если порт занят, runner сообщает выбранный порт 8000–8019. После обновления сборки обновите вкладку Ctrl+F5. Готовый frontend отдаёт backend; второй процесс не требуется. Остановка запуска в терминале: **Ctrl+C**.

Без отдельного окна:

```powershell
python run.py --background
python run.py --stop
```

Повторный запуск сообщает адрес работающего экземпляра. Остановка затрагивает только экземпляр с его локальным ключом управления; посторонние процессы не завершаются. Runner сохранён с существующими настройками пользователя. Сервер слушает localhost.

## Поиск и импорт

### Синхронизация без скачивания LRC

1. Импортируйте разбор и прикрепите свою MP3 в редакторе.
2. Нажмите **«Найти синхронизацию»** в карточке песни, редакторе или плеере. Поиск подставляет название, исполнителя и длительность записи; название/исполнителя можно исправить, альбом — указать, если он известен.
3. Нажмите **«Найти варианты»**. Сравните название версии (например, Live), альбом, длительность и разницу с вашей записью. При необходимости вставьте прямую ссылку, например `https://lrclib.net/tracks/20902008`, и нажмите **«Открыть ссылку»**.
4. Выберите результат, проверьте таблицу совпадений и прослушайте **свою** запись в предпросмотре. Общий сдвиг задаётся в секундах. Проверьте строки без совпадения; служебные схемы боя и инструментальные строки не считаются вокалом.
5. Нажмите **«Применить синхронизацию»**. При замене уже существующих отметок требуется отдельное согласие. Текст, IDs и аккорды сохраняются. В редакторе работает обычная отмена; в плеере — **«Отменить изменение карты»**, затем **«Сохранить временную карту»**.
6. Откройте плеер и нажмите **«Воспроизвести»**. Подсветка следует фактическому времени аудио. Если у записи только времена строк, в **«Настройках исполнения»** можно включить **«Приблизительную подсветку слов»** (по умолчанию выключена).

Сервис может быть недоступен или не иметь подходящей версии. В этом случае остаются **«Импортировать LRC»** и **«Разметить вручную»**. Они открывают только выбранный инструмент. Ручной импорт принимает простой LRC, Enhanced LRC и Lyricsfile 1.0 (`.yaml/.yml`); все варианты сначала показывают предпросмотр. Обычный текст без времён не создаёт карту.

### Какие отметки используются

| Данные | Подсветка |
| --- | --- |
| Полные исходные интервалы слов | Последовательность и заливка по этим интервалам |
| Исходные начала слов без концов | Начала точные относительно данных источника; длительность заливки оценивается только для показа, незавершённые интервалы ограничены 2,5 секунды |
| Только начала/концы строк | Подсветка строки; при включённой настройке — приблизительное распределение слов по длине и пунктуации |
| Длинный интервал / проигрыш / сомнительная разметка | Подсветка строки либо отсутствие автоматической подсветки; без выдуманных словных отметок |

LRCLIB возвращает `plainLyrics`, `syncedLyrics` и новый `lyricsfile` YAML; наличие `hasWordSync` проверяется по самим словным данным. В JSON песни полные интервалы хранятся в `words`, неполные исходные интервалы — в необязательном `wordStarts`. Приблизительные интервалы отображения в документ не записываются. Одновременные голоса, неоднозначные повторы и разделение одной LRC-строки на несколько строк без словных времён требуют ручной проверки. Аккорды остаются над буквами отдельным слоем, инструментальные аккорды располагаются с промежутками и переносами.

### Язык, внешний вид и конфиденциальность

**Настройки → Язык интерфейса → English / Русский** меняет весь интерфейс и сохраняется в этом браузере. Язык песни, её текст, пользовательские названия, исполнители и обозначения аккордов не переводятся. Шрифты системные, иконки локальные; аналитики и внешних изображений нет. Нативные полосы прокрутки оформлены CSS; в режиме высокой контрастности используются системные цвета.

Внизу обычных экранов находятся @qvertick, [GitHub](https://github.com/qvertick/In-Tune), **«Конфиденциальность»** и **«Источники и лицензии»** на обоих языках. В плеере footer доступен внизу панели настроек; чистый и полноэкранный режимы скрывают его.

Поиск передаёт выбранным сайтам поисковый запрос, а LRCLIB — название, исполнителя и заполненный альбом либо ID ссылки. Длительность сравнивается локально. MP3 не загружается в эти сервисы. JSON-экспорт не включает аудио. Каталог проекта может отдельно синхронизироваться OneDrive или другой программой — приложение этим не управляет.

LRCLIB API работает без ключей и регистрации для чтения. Условия и доступность могут меняться: [документация](https://lrclib.net/docs), [условия API](https://lrclib.net/developers/terms). Наш адаптер ограничивает обращения до 20 в минуту и одного одновременно, использует паузу 500 мс, таймаут 12 с, кеш на 5 минут (64 записи / 8 МиБ) и соблюдает `Retry-After`. Это локальные ограничения приложения, не обещание пропускной способности LRCLIB. Права на исходные тексты/разборы остаются у их правообладателей. YAML-парсер `yaml` — ISC; спецификация [Lyricsfile](https://github.com/tranxuanthang/lyricsfile) — CC0 1.0, версия 1.0 пока черновая.

### Импорт разборов

1. В библиотеке введите **«Название песни или исполнитель»**, переключите **«Найти разбор»** и нажмите **«Найти разборы»**. Enter запускает поиск. Вкладка **«Моя библиотека»** фильтрует уже сохранённые песни.
2. Откройте **«Предпросмотр»**, проверьте слова, аккорды, разделы и предупреждения, затем **«Добавить в библиотеку»**. Просмотр сам ничего не сохраняет.
3. Прямую ссылку можно вставить в общую поисковую строку или поле **«Ссылка на разбор» → «Предпросмотр ссылки»**.
4. Если источник недоступен: **«Вставить текст с аккордами вручную»**. Поддерживаются строки аккордов над текстом и `[Am]аккорды [E]внутри строки`. Не копируйте меню и комментарии сайта. Перед сохранением также есть предпросмотр.

Akkords.pro получает бейдж «Рекомендуем» среди соответствующих запросу результатов. Это предпочтение источника, а не выдуманная оценка качества. Разные исполнители не объединяются по одному названию. При повторном импорте URL можно открыть существующую песню либо создать отдельную копию.

### Фактическая поддержка сайтов

Проверены реальные HTTPS-страницы 26 октября 2026 года:

| Источник | Поиск в приложении | Предпросмотр / импорт по ссылке | Ограничение |
| --- | --- | --- | --- |
| Akkords.pro | Работает | Работает | Открытые HTML-страницы; зависит от доступности сайта. |
| MyChords.net | Недоступен | Работает | Исследованный поиск возвращает форму без результатов; можно открыть сайт и вставить ссылку на песню. |
| Chorder.ru | Отключён | Работает | Автоматический поиск запрещён robots.txt. Ссылка на источник сохраняется и показана в карточке. |
| Ultimate Guitar | Отключён | Работает для открытых Chords / Ukulele Chords | Автоматический поиск запрещён robots.txt; платные/закрытые форматы и проверки доступа не обходятся. |

Поиск и импорт каждого сайта имеют раздельные состояния. Ошибка доступа не маскируется «нулём результатов». При изменении сайта адаптер может потребовать обновления. CAPTCHA, авторизация и платный доступ не обходятся. Подробнее о структуре страниц, условиях и проверках: [docs/SOURCES.md](docs/SOURCES.md).

Адаптеры не исполняют внешний JavaScript и не вставляют HTML в интерфейс. Backend разрешает только конкретные HTTPS-домены/маршруты, проверяет DNS и редиректы, ограничивает размер, время и частоту запросов. Приложение не является универсальным proxy.

## Редактор и MP3

Сохранены разделы, строки, палитра, popover замены одного аккорда, добавление нового аккорда, перенос выбором позиции, удаление, отдельная подтверждаемая замена всех, undo/redo и автосохранение. Обычные `#`, `b` и символы ♯/♭ принимаются. Несколько аккордов внутри слова и инструментальные строки поддерживаются. Перетаскивания пока нет.

В редакторе нажмите **«Добавить MP3»**. Источник разбора не предоставляет аудио автоматически. Используйте свой файл; загрузчик Spotify/SoundCloud не добавлен. Файл проверяется как настоящий MP3, лимит — 50 МиБ. Замена записи помечает имеющиеся временные отметки для проверки.

Карточка показывает наличие источника, аудио, синхронизации и дорожек. У импортированной песни есть **«Открыть источник»**, автор и вариант подбора, когда они доступны.

## Разметить строки под запись

1. В редакторе нажмите **«Открыть плеер»**.
2. Выберите **«Разметить вручную / LRC»**, затем первую строку.
3. Запустите запись кнопкой **«Воспроизвести для разметки»**.
4. В начале строки нажимайте большую **«Отметить начало → M»** или физическую клавишу **M**. Записывается фактическое время аудио и выбирается следующая строка. Горячая клавиша не срабатывает внутри полей ввода.
5. Доступны предыдущая/пропущенная строка, **«Отменить отметку»**, перемотка и общий сдвиг. Начало следующей отмеченной строки закрывает предыдущую. Для паузы или проигрыша можно явно отметить конец строки.
6. В **«Проверка разметки выбранной строки»** можно прослушать участок и поправить начало/конец числом. При желании — интервалы каждого слова.
7. Нажмите **«Сохранить временную карту»** и дождитесь **«Сохранено»**. До этого карта остаётся рабочим черновиком плеера с аварийной копией в браузере. При переходе к редактору правки передаются на автосохранение; при закрытии несохранённой страницы есть предупреждение.

Не требуется размечать слова. При наличии только строк подсвечиваются строки. Точная подсветка слов включается только при полной соответствующей разметке. Равномерные фиктивные времена не создаются. Изменение текста помечает затронутую строку для проверки, остальные строки сохраняют отметки.

### LRC

В инструментах разметки раскройте **«Импорт времён из LRC»**, выберите `.lrc` либо вставьте текст. Поддерживаются обычные отметки строк `[mm:ss.xx]`, несколько отметок одной строки и `offset`. Перед применением показаны совпавшие и пропущенные строки. Текст, разделы, палитра и позиции аккордов сохраняются. Порядок и одинаковые припевы учитываются; чужая аранжировка не применяется вслепую. Расширенный LRC с отметками слов не заявлен как поддержанный формат.

## Плеер и режимы звучания

### Следование экрана и перемотка

**Вступления, паузы и проигрыши.** Над областью текста показаны текущий раздел, компактная схема боя и ближайшие вокальные строки для предварительного чтения. При известном следующем вступлении отсчёт «Вокал через … с» берётся из времени общего плеера. Будущие слова не подсвечиваются как звучащие. При известном конце фразы активное выделение снимается на этой границе; прежняя строка остаётся контекстом. Для прокрутки не требуется активное слово — используется тот же механизм следования, что и при вокале.

Следующая отметка или конец файла сами по себе не подтверждают конец пения. Без конца фразы плеер показывает «Конец фразы не отмечен». Для старой карты с концом последней строки ровно на границе файла и отдельной неразмеченной концовкой показано «Конец фразы требует проверки»: точный момент не придумывается. Исправить его можно в ручной разметке. Сохранённые времена при этом не меняются автоматически.

**Инструментальные аккорды.** Привязки и текстовые рифы отображаются отдельными читаемыми последовательностями; `}x4`, `}х4` и число повторов раздела становятся только метаданными отображения. Оригинальные строки и обозначения остаются в JSON. Нет миграции или автоматического разворачивания повторов в одинаковые интервалы. Без времён ряд статичен, без случайного выделения. С известными началами и концами показываются текущий аккорд и прогресс его интервала. «Круг 2 из 4» без границ кругов не выводится.

Для структурированных аккордов нажмите **«Разметить аккорды»**, включите общий плеер и нажимайте **«Отметить следующий аккорд»** на реальных сменах. Предыдущий открытый интервал закрывается следующим нажатием; последний завершается кнопкой **«Отметить конец аккордов»**. Можно вручную исправить секунды. Нажмите **«Сохранить временную карту»**; отмена работает через общую историю. Границы самой инструментальной строки для этого необязательны. Рифы, записанные только обычным текстом без аккордных привязок, остаются статичными.

**Бой остаётся инструкцией.** Он не участвует в вокальной разметке и подсветке слов. Одних BPM, размера и стрелок недостаточно для точной анимации: в текущем формате нет подтверждённых начала ритмического цикла и позиций ударов. Поэтому схема показывается статично с сохранением пауз и приглушений.

Настройки плеера сгруппированы в «Текст и чтение», «Звучание» и повтор A–B; длинное пояснение подсветки раскрывается отдельно. На телефоне панель открывается кнопкой **«Настройки плеера»** со значком ползунков, освобождая место тексту. Длинные инструментальные ряды имеют собственную нативную горизонтальную прокрутку; страница горизонтально не прокручивается.

Во время воспроизведения прокручивается только область текста: текущая строка остаётся примерно в верхней половине, а у длинной перенесённой строки отслеживается активное слово. Положение определяется фактическим временем выбранной аудиодорожки. Пауза останавливает самостоятельное движение. Изменения ширины, размера шрифта и полноэкранного режима учитываются автоматически.

Колесо, касание, перетаскивание полосы и клавиши листания при фокусе области текста временно приостанавливают следование. Нажмите **«К текущей строке»**, чтобы вернуться и продолжить. Кнопка не меняет размеры области и положение нативного ползунка. Программная прокрутка не приостанавливает следование.

При пользовательском переходе назад **на 5–10 секунд включительно** аудио перематывается сразу, а выделение проходит назад к новой позиции за **350 мс**. Это только визуальное движение; звук не играет задом наперёд и отметки не меняются. При продолжающемся воспроизведении эффект завершается на актуальном времени аудио. Переходы на 3 или 20 секунд такого эффекта не имеют. Возврат с 8 секунд на начало анимируется, с минуты — сразу показывает начало.

Правила одинаковы для ползунка, нажатия на размеченную строку, клавиатуры и кнопки начала. Перетаскивание классифицируется один раз при отпускании относительно позиции перед началом жеста. Новый переход отменяет старую анимацию. Повтор A–B не считается пользовательской перемоткой. В **«Настройках исполнения» → «Подсветка текста»** можно выключить выделение; тогда обратного пробега нет. При reduced motion переходы мгновенные. Для карты только со строками используются только имеющиеся времена строк.

### Если LRCLIB сообщает об ошибке

Запись по ссылке `https://lrclib.net/tracks/20902008` запрашивается через документированный `https://lrclib.net/api/get/20902008`. Проверка 28 октября 2026 показала чередование настоящего **503 ServerOverloaded** с `Retry-After: 1` и успешного **200**. Ответ 503 был одинаковым при прямом HTTPS-запросе из Python и через защищённый адаптер; ID, endpoint и парсинг успешной записи корректны.

Интерфейс различает отсутствие записи/синхронизации, ограничение запросов, перегрузку, другие ошибки сервиса, сеть/таймаут и разбор ответа. Кнопка **«Повторить запрос»** повторяет последнее действие только по нажатию. Ожидание показывается лишь по настоящему Retry-After либо вычисленному ограничению нашего адаптера; без такого основания таймер не придумывается. Автоматических сетевых повторов нет. Логи `data/server.log` содержат HTTP-статус, безопасный набор заголовков, тип ответа и цепочку типов исключений, без текстов песен и произвольного содержимого ответа. Технические доказательства проверки сохранены в локальном `.tmp/lrclib-diagnosis.md`.

В обновлённом приложении открытие этой ссылки также проверено через браузер: первый запрос получил 503, один ручной повтор — **200**, «Стук», Кино, 231 с, отметки строк. Это подтверждает работоспособность ID/маршрута/парсера и восстановления после ошибки; доступность внешнего сервиса может меняться.

Есть play/pause, перемотка, длительность, громкость, скорость с `preservesPitch` браузера, A–B, переход по разделу/размеченной строке, размер текста, чистый экран и fullscreen при поддержке браузером. Аудио читается потоком, не декодируется целиком в несколько массивов WAV.

Синхронизация опирается на `HTMLMediaElement.currentTime`. Пауза останавливает подсветку, перемотка и возвращение из фоновой вкладки восстанавливают актуальное место. Без карты автоматической прокрутки нет.

- **Оригинал** — исходный MP3.
- **Вокал** / **Аккомпанемент** — готовые выделенные дорожки.
- **Свой микс** — независимые громкости и mute обеих дорожек.
- **Только текст** — звук выключен; отдельные монотонные часы используют сохранённую карту.

Оригинал и выделенные дорожки не звучат одновременно. В миксе дорожки вместе стартуют, ставятся на паузу и перематываются; плеер контролирует расхождение. Это потоковое браузерное воспроизведение, не студийный сэмпл-точный движок.

**Микрофон не используется.** Старые голосовые модули изолированы от основного интерфейса и по умолчанию не имеют API-маршрутов. Vosk не загружается при обычном запуске. Установленная пользователем Whisper tiny сохранена как необязательный дополнительный анализ в редакторе и не нужна для основного сценария.

В плеере раскройте **«Вокал и аккомпанемент»** → **«Подготовить дорожки»**. Выполняется одна фоновая задача; показывается этап, доступны отмена и повторная проверка. После готовности включаются режимы вокала, аккомпанемента и микса. Готовые файлы сохраняются и открываются повторно без перерасчёта. При замене оригинала старый результат не используется.

На этом компьютере установлен отдельный CPU-движок Demucs и **одна** модель htdemucs. Если переносите проект, явная установка:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-separation.ps1 -DownloadModel
```

Окружение — `.venv-separation`, веса — `models/separation/htdemucs`. Проверенные веса: **84 141 911 байт, около 80 МиБ**. Основной редактор/плеер работают без этого окружения. Лицензии, точные версии, установка, диагностика, NVIDIA и измерения: [docs/SEPARATION.md](docs/SEPARATION.md).

## Данные, экспорт и резервные копии

- `data/songs.sqlite3` — документы песен; JSON schemaVersion 1 с необязательным `origin`.
- `data/jobs.sqlite3` — сохранённая очередь и состояния. Прерванная перезапуском задача получает понятное состояние, не остаётся вечно «в работе».
- `data/audio/` — исходные MP3.
- `data/stems/` — вокал/аккомпанемент и метаданные привязки к исходному файлу.
- `data/server.log` — журнал фонового запуска.

Перед этим обновлением создана резервная копия `backups/before-player-20261026-171717/`. Миграция хранилища добавляет только учёт версии SQLite и не переписывает существующие документы/аудио. Старые документы без `origin` читаются. Исходная команда запуска и установленные пользователем модели сохранены.

Новая резервная копия:

```powershell
python scripts/backup_data.py
```

Для полного переноса остановите приложение и перенесите каталог данных целиком. Резервные копии, базы, аудио, модели, окружения и временные файлы исключены из Git. Не храните резервную копию внутри самого каталога данных.

**JSON-экспорт — редактируемая песня, а не полный архив проекта:** включает текст, аккорды, источник, разметку и параметры; не включает MP3 и выделенные дорожки. После импорта аудио прикрепляется отдельно. При ошибке автосохранения редактор оставляет аварийный черновик в браузере.

Каталог данных можно задать до запуска через `VLAD_DATA_DIR`. Название меняется в `frontend/src/config.ts`. Один локальный пользователь, один сервер; совместное редактирование и доступ с телефона по LAN не настроены.

## Обновлённый интерфейс и приветствие

Откройте [приветствие](http://127.0.0.1:8000/welcome) или [библиотеку](http://127.0.0.1:8000/library). На настроенном компьютере запуск из папки проекта:

```powershell
python run.py --background
```

Остановка только запущенного этим скриптом приложения: `python run.py --stop`. После изменения frontend выполните `cd frontend`, `pnpm build`, затем вернитесь в корень. Backend отдаёт готовую сборку; отдельный Vite для обычного использования не нужен.

Первый вход через `/` показывает приветствие. Следующие входы восстанавливают последнюю рабочую страницу; плеер восстанавливается редактором без автоматического воспроизведения. В настройках можно включить «Показывать приветствие при запуске». Логотип открывает приветствие в любой момент. Прямые ссылки `/songs/{id}` и `/songs/{id}/player` сразу открывают песню независимо от этой настройки. Кнопка «Продолжить» появляется только для существующей последней песни. Предпочтения хранятся в браузере, отдельно от документов SQLite.

В общей тёмной теме обновлены библиотека, поиск, редактор, меню аккордов, диалоги, настройки и плеер. Цвета, типографика и состояния контролов собраны в `frontend/src/theme.css`. Системные шрифты поддерживают кириллицу и не требуют внешних запросов. Тексты новых экранов переведены на English через общий словарь. Песни при смене языка не переводятся.

Музыкальный SVG локальный и авторский. Свет под указателем работает только в видимом первом разделе, объединяет события через RAF и не обновляет React на движении мыши. На touch/reduced motion фон статичен. Авторский пример **не имеет звука**: он автоматически оживает, когда видно не менее 35% блока. Есть пауза, продолжение и запуск сначала. Вне экрана и в скрытой вкладке время примера замораживается, а при возвращении продолжается с того же места. При reduced motion пример статичен и доступен ручной переход к следующей строке. Это отдельная заданная вручную демонстрация; рабочий плеер продолжает использовать время реальной записи.

Шкала справа содержит четыре настоящих перехода и декоративные деления. У отметок есть подсказки при наведении/фокусе; Escape скрывает карточку. На ширине до 1000 px шкала становится компактной полосой под шапкой. Активность шагов определяется прокруткой; сами шаги открывают поиск, синхронизацию или панель микшера последней песни. Если у последней песни нет MP3, шаг звучания открывает редактор с действием «Добавить MP3», а не пустой микшер. Если песни нет вовсе, открывается библиотека для выбора. Внизу — четыре стандартные открытые аппликатуры Am/C/G/Em: выбор мышью, касанием или стрелками клавиатуры, без звука и сети. В схеме струны идут от толстой E слева к тонкой e справа; числа в кружках обозначают пальцы.

### Своё фоновое видео позже

Видео сейчас отсутствует и не скачивается. Чтобы подключить своё:

1. Положите короткий зацикленный файл в `frontend/public/media/welcome-loop.webm` (или `.mp4`). Каталог `media` можно создать при добавлении файла.
2. В `frontend/src/config.ts` замените `WELCOME_VIDEO = null` на:

   ```ts
   export const WELCOME_VIDEO: { src: string; type: string } | null = {
     src: "/media/welcome-loop.webm",
     type: "video/webm",
   };
   ```

3. Выполните `pnpm build` в `frontend` и обновите страницу. Для MP4 укажите `.mp4` и `video/mp4`. Возврат к `null` полностью отключает видео.

Видео служит приглушённым фоном, запускается без звука, при уходе первого раздела/скрытии вкладки приостанавливается. При reduced motion не воспроизводится. Сам видеофайл и качество его кодирования пока не проверялись: пользовательское видео ещё не предоставлено. Для слабого ноутбука предпочтителен небольшой файл без высокой частоты кадров.
