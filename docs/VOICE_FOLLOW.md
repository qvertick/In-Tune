# Следование за голосом

> Этот документ описывает прежний режим без временной карты. Новый режим с независимыми часами, потоковым Vosk и фоновой коррекцией описан в [TIMELINE.md](TIMELINE.md). Оконный механизм ниже сохранён как запасной вариант для песен без отметок.

## Что реализовано

Цепочка: браузерный микрофон → AudioWorklet → моно → ресемплинг → PCM s16le 16 кГц → локальный Vosk small → сопоставление слов с известным текстом → текущая строка. MP3, фонограмма, временная разметка песни и платные сервисы не нужны. Аудио этой функции не записывается в библиотеку и не отправляется во внешние сервисы.

Языки: русский (`vosk-model-small-ru-0.22`), украинский (`vosk-model-small-uk-v3-nano`), английский (`vosk-model-small-en-us-0.15`). Модель выбирается явно. На текущем компьютере скачана только русская модель, размер архива 46 236 750 байт. Остальные устанавливаются по показанной в интерфейсе команде `install-follow.ps1 -Language uk` или `en`. Пакеты закреплены в `backend/requirements-follow.txt`.

Vosk выбран для CPU и небольших моделей. [Официальный каталог](https://alphacephei.com/vosk/models) рекомендует small-модели для настольных компьютеров и указывает примерно 300 МБ памяти для небольших моделей; фактическая память процесса здесь не измерялась. У кода и этих моделей Apache 2.0. [Официальный пример PCM API](https://github.com/alphacep/vosk-api/blob/master/python/example/test_simple.py) и [исходник API](https://github.com/alphacep/vosk-api/blob/master/python/vosk/__init__.py) подтверждают приём PCM и загрузку по локальному пути. Приложение всегда передаёт путь, чтобы библиотека не скачивала модель автоматически. Модели обучены на речи: качество на пении отдельно не подтверждено.

## Звук и задержки

- В браузере хранится не более четырёх секунд звука. Окно — 3,2 секунды, минимальный шаг — 1,2 секунды, перекрытие — две секунды.
- Между AudioWorklet и основным потоком допускается только одно не подтверждённое сообщение. При задержке вкладки блоки отбрасываются, временная шкала сохраняется, после разрыва набирается свежий контекст.
- В каждый момент отправляется один запрос. Пока он обрабатывается, сохраняется только свежий звук. Ожидающей очереди окон нет. Медленная обработка приводит к пропускам старых окон, а не к накоплению задержки.
- Используется фактический `AudioContext.sampleRate`. Stereo усредняется до mono; `OfflineAudioContext` выполняет ресемплинг с фильтрацией, затем отправляется signed 16-bit little-endian PCM. Частота 48 кГц не переименовывается в 16 кГц. Backend проверяет формат, длину и временные границы.
- Очень тихие окна и постоянная составляющая не запускают распознавание. Проверка энергии не умеет отделять гитару от голоса. Нулевой сигнал проверен отдельно: он не продвигает строку и не вызывает Vosk.
- Один общий замок вычислений, один живой сеанс и один запрос в обработке. Фоновый анализ и следование взаимоисключаются. Модель переиспользуется между окнами; при смене языка или провайдера предыдущая акустическая модель освобождается до загрузки новой.
- Результаты с обработкой дольше пяти секунд не меняют гипотезу. Клиент также отбрасывает слишком поздний ответ. При остановке отменяется сеанс; Vosk проверяет отмену между блоками по 200 мс аудио. Начатую нативную загрузку модели нельзя мгновенно прервать, но её результат не будет применён.

Проверка локальным установленным голосом Windows Microsoft Irina Desktop, **синтезированная речь без гитары, не живое пение**: все четыре строки авторского примера были найдены по порядку. Последующий нулевой сигнал удержал строку. WAV: mono PCM, 16 кГц, около 14 секунд. Проверка прошла через настоящие HTTP-обработчики FastAPI и настоящий Vosk, без подмены распознавания.

Прогон через тестовые HTTP-обработчики: первое окно с загрузкой модели — **1926 мс**, медиана обработки последующих полных окон — **934 мс**, максимум — **2219 мс**. На части окон обработка превышала шаг 1,2 секунды; поэтому предусмотрен пропуск старого звука.

Отдельный прогон 26 октября 2026 года через работающий **TCP-сервер http://127.0.0.1:8000**: первое окно — **2338 мс**, медиана последующих — **593 мс**, максимум — **2338 мс**. Все четыре строки найдены по порядку, тишина не сдвинула позицию. Временная тестовая песня удалена, пользовательские песни не изменялись.

Это вычислительная задержка, не полная задержка подсветки. Первый ответ ожидается только после накопления 3,2 секунды звука плюс загрузка/обработка. В дальнейшем задержка зависит от положения слов в окне, нагрузки CPU, доставки звука и сопоставления. Эти числа не обещают такую же скорость на другом ноутбуке или при живом пении.

Повторить измерение на своём PCM WAV:

```powershell
python scripts/benchmark_follow.py .tmp/voice-follow-ru.wav --output .tmp/follow-benchmark.json
# Проверка через запущенное приложение:
python scripts/benchmark_follow.py .tmp/voice-follow-ru.wav --live-url http://127.0.0.1:8000 --output .tmp/follow-live-benchmark.json
```

Скрипту нужен установленный Vosk и WAV 16 кГц mono PCM16. Тестовый WAV не включён в Git. Скрипт содержит текст авторского примера, использует временную базу и не меняет пользовательские песни. Измеряется обработка подготовленного файла, а не задержка физического микрофона или браузерного ресемплинга.

Если реальные значения регулярно превышают шаг 1,2 секунды, приложение будет пропускать окна. Если превышают пять секунд, место удерживается. Следующий конкретный эксперимент в таком случае: сохранить один потоковый `KaldiRecognizer` на сеанс и подавать только новые блоки по 200 мс, вместо повторного декодирования перекрытия. Сравнить медиану/максимум задержки и число ошибочных переходов на той же записи. Увеличивать модель до этого измерения не нужно.

## Как выбирается строка

Исходный текст для показа сохраняется. Для поиска нормализуются Unicode, регистр, пунктуация, апострофы, пробелы и `ё/е`. Сравниваются последовательности слов, допускаются небольшие ошибки и пропуски распознавания. Основной поиск ограничен текущим контекстом. Одного распространённого слова недостаточно: нужна последовательность как минимум с двумя различными содержательными словами.

Позиция хранится по словам, а не автоматически увеличивается на единицу после каждого ответа. Повторяющиеся окна и уже использованные временные отметки слов не продвигают позицию повторно. В одинаковых припевах выбирается ближайший контекст. При сильном сомнении позиция удерживается. После нескольких неудачных окон включается ограниченный поиск по всему тексту: нужен длинный характерный фрагмент и повторное подтверждение новым звуком. Неоднозначные одинаковые припевы не служат основанием для дальнего скачка.

Ручной выбор строки немедленно меняет позицию, увеличивает поколение сеанса, очищает свежий буфер и прежнюю гипотезу, прерывает старый запрос. Ответ другого поколения игнорируется и браузером, и backend. Затем снова набирается короткое окно. Это помогает начать с середины и восстановиться после ошибки.

Это начальная эвристика, а не доказанное распознавание любого исполнения. Очень короткие строки, повторяющиеся слова, одинаковые соседние припевы, растянутые гласные, пение без отчётливых согласных, инструментальные места и громкая гитара могут удерживать или ошибочно определять место. Подсветка отдельных слов и распознавание гитары не реализованы.

## Проверить на ноутбуке

1. Откройте песню с сохранённым текстом → «Исполнять». Для первой проверки оставьте свободный режим и выключите метроном/плеер.
2. Выберите язык, нажмите стартовую строку, затем «Следовать за голосом» и разрешите микрофон. Проверьте выбор аудиовхода до включения следования.
3. Прочитайте текст обычным голосом. Дождитесь первого результата. Проверьте текущую строку, затем паузу 5–8 секунд. Она не должна продолжать двигаться на тишине.
4. Спойте без гитары. Попробуйте замедлиться, повторить строку и начать с середины после ручного нажатия. При ошибке раскройте диагностику и сравните распознанный фрагмент со своим текстом.
5. Добавьте негромкую акустику. Микрофон приблизьте к голосу, гитару отведите дальше. Сначала простые редкие удары, затем обычный бой. Сравните частоту ошибок и задержку с пунктом 4. Одинаковое качество не гарантируется.
6. Нажмите «Остановить следование». Индикатор разрешённого микрофона в браузере должен погаснуть. Повторный старт должен открывать один поток. Проверьте отказ в разрешении и отключение устройства.

Автоматические тесты проверяют сопоставление, повторы, тишину, одинаковые припевы, ручной переход, устаревшие ответы, PCM, границы буфера, отмену, ошибки и очистку графа. UI проверен в JSDOM; это не проверка реального устройства, браузерного звука или живого пения.
