# Источники песен

Пакет `backend.sources` предоставляет готовый `APIRouter` и не требует новых зависимостей: HTML, HTTPS и DNS обрабатываются стандартной библиотекой Python. Используются уже установленные FastAPI/Pydantic. Отдельный `requirements-sources.txt`, изменение lock-файла и загрузка моделей не нужны.

## Подключение и контракт

Владелец приложения подключает роутер один раз:

```python
from backend.sources import router as sources_router
app.include_router(sources_router)
```

Пакет не меняет `main.py`, схему, хранилище или frontend. Предпросмотр не сохраняет песню. Сохранение выбранного пользователем результата выполняется существующим API песен. Схема приложения должна принимать необязательный `origin: {site, url, author?, variant?}`. `site` — ID источника, `url` — проверенная конечная ссылка. `source` песни/строк/аккордов остаётся `manual`: импорт не считается выводом модели.

| Запрос | Ответ |
| --- | --- |
| `GET /api/sources` | `{sources: [{id, name, host, searchAvailable, importAvailable, searchUrl, note}]}` |
| `GET /api/sources/search?source=ID&query=...` | `{source, results: [{title, artist, url, source, variant?}], error?: string}` |
| `GET /api/sources/preview?url=...` | `{song, warnings: string[], source: {id, name, url, author?, variant?}}` |
| `POST /api/sources/manual` с JSON `{title, artist, text}` | Тот же конверт предпросмотра; `source: {id: "manual", name: "Ручной ввод", url: ""}`, без `origin` |

`searchUrl` в списке содержит `{query}`: клиент заменяет его на URL-кодированный запрос, чтобы пользователь мог открыть поиск в браузере. Это ссылка для человека, а не разрешение backend обращаться к отключённому поиску. Стабильные ID: `akkords`, `mychords`, `chorder`, `ultimate`.

Ошибки поиска возвращаются в поле `error` при HTTP 200 для независимых параллельных запросов UI. Пустой `results` без `error` означает только распознанный шаблон отсутствия результатов. Ошибки загрузки/защиты/разметки не маскируются пустым списком. Ошибки предпросмотра используют HTTP 400/422/429/502/503/504 с русским `detail`. Русскими также являются `note`, предупреждения и сообщения ручного ввода. Предпросмотр и ручной импорт возвращают `Cache-Control: no-store`.

## Что действительно проверено 26 октября 2026 года

Сетевые проверки выполнялись обычным HTTPS-клиентом с честным `User-Agent: InTune/1.0 (local songbook; user-initiated import)`, без cookies, авторизации, выполнения JavaScript и обхода проверок доступа. Исходный HTML и тексты песен не сохранены в репозитории; ниже только ссылки, структура и счётчики. Проверки сайта исследовательским браузером и прямым HTTP могут отличаться: например, исследовательский браузер не открыл Ultimate Guitar, но прямой безопасный транспорт успешно загрузил и разобрал его.

| Источник | Поиск backend | Импорт по ссылке | Наблюдение |
| --- | --- | --- | --- |
| Akkords.pro | Да | Да | Открытый HTML поиска и `p.chords`; проверенная страница вернула HTTP 200. |
| MyChords.net | Нет | Да | Проверенная песня вернула HTTP 200. `/ru/search?q=...` возвращал форму без результатов и без явного сообщения «ничего не найдено». Нельзя выдавать sidebar за результаты поиска. |
| Chorder.ru | Нет | Да | Проверенная песня вернула HTTP 200, текст есть в `pre#song-text`. `robots.txt` запрещает `/search*`; backend не выполняет поиск. |
| Ultimate Guitar | Нет | Да, открытые Chords/Ukulele Chords | Проверенная песня вернула HTTP 200 с доступным текстом в HTML-атрибуте `data-content` элемента `.js-store`. `www.ultimate-guitar.com/robots.txt` запрещает `/search.php`; backend не выполняет поиск. |

Все четыре `importAvailable` равны `true` именно потому, что проверенные реальные страницы импортированы конечным транспортом и парсером и их результаты прошли `Song.model_validate`, включая `origin`. Флаг означает реализованную и проверенную возможность; он не обещает доступность каждого материала или сети в момент будущего запроса. Защищённая, платная или изменённая страница возвращает понятную ошибку и предложение ручного ввода.

### Akkords.pro

- [Проверенная песня «Стук»](https://akkords.pro/songs/kino/stuk/): 7 разделов, 30 строк, 54 поддерживаемых в текущей схеме аккорда после устранения дублирования припевов. `E5`/`G5` сохранены как неподдерживаемая текстовая нотация с предупреждением; они не включены в этот счётчик.
- Настоящая форма сайта: GET `https://akkords.pro/?s={query}`.
- Контейнер результатов: `.apx-top-songs--archive`; каждая ссылка `.apx-top-songs__link`, название `.apx-top-songs__title`, исполнитель `.apx-top-songs__artist`. Sidebar и рекомендации не собираются. Максимум 20 результатов, без обхода следующих страниц.
- Запрос пользователя **«мама анархия»** действительно вернул [«Мама-анархия» — Кино](https://akkords.pro/songs/kino/mama-anarhija/). Последующая загрузка этой ссылки также успешно импортирована и прошла проверку схемы: 14 разделов и 76 аккордов.
- Текст песни извлекается только из `p.chords`, с сохранением переносов/пробелов; исполнитель берётся из ссылки каталога артиста, автор подбора — `.apx-author-card__name`. Комментарии, реклама и инструкции скриптов не импортируются.
- [robots.txt](https://akkords.pro/robots.txt) при проверке не запрещал эти страницы и поиск.

### MyChords.net

- [Проверенная песня «Стук»](https://mychords.net/ru/kino/1166-kino-stuk.html): 5 разделов, 23 строки, 78 аккордов; объект песни прошёл проверку схемы.
- Реальная форма: GET `/ru/search?q={query}`. На странице также объявлены `/ru/ajax/autocomplete` и `/ru/search/meaning`; они не считаются готовым API и backend их не использует. Проверялись запросы «Стук», «Кино Стук», а также обычный параметр формы `src=1`; получалась только форма. Публичный JS содержит зависимость страницы поиска от cookies; backend не имитирует браузер и не пытается её обходить.
- Парсер ограничен `.w-words__text`. В `.pline .c-subline` первая `.subline` содержит аккорды, вторая — соответствующий отрезок текста. Их объединение создаёт Unicode-якоря, а не дублирует аккорды как слова. `.single-line` содержит отдельные заголовки/инструментальные строки.
- Аккорды, выходящие за длину своего отрезка, привязываются к его концу с предупреждением. Вариант берётся из подписи выбранной ссылки, автор добавляется только из явно обозначенной пользовательской ссылки.
- [robots.txt](https://mychords.net/robots.txt) содержит запреты для отдельных именованных ботов, а общая группа запрещает загрузки, редактирование и восстановление пароля. Приложение идентифицируется своим именем InTune и проверяет применимую группу правил; сторонние загрузки и закрытые API не используются.

### Chorder.ru

- [Проверенная песня «Стук»](https://chorder.ru/songs/kino/27-stuk-akkordy): 5 разделов, 20 строк, 48 аккордов; объект песни прошёл проверку схемы.
- Настоящая форма поиска: GET `https://chorder.ru/search?q={query}`. После обнаружения запрета `/search*` в [robots.txt](https://chorder.ru/robots.txt) автоматический поиск отключён. Ссылка остаётся доступной пользователю для открытия в браузере.
- Извлекается только `pre#song-text`, название — `h1`, исполнитель — `.song-artist`.
- Поддержаны исходные заголовки `[[куплет|B:DUD-DUD]]`, `[[куплет_2]]`, `[[припев]]`: метка боя не становится частью названия раздела. Повторный пустой заголовок ссылается на уже разобранный одноимённый раздел. Повторный заголовок с полным текстом не размножает этот текст.
- Исходная ссылка сохраняется в `origin.url` и `source.url`, чтобы интерфейс мог показать атрибуцию источника.

### Ultimate Guitar

- [Проверенная песня «Стук», tab 2410047](https://tabs.ultimate-guitar.com/tab/2410047): 7 разделов, 32 строки, 164 аккорда; объект песни прошёл проверку схемы. Публичные данные содержали тип `Chords`, вариант 1 и автора `NSpen1`.
- Настоящий маршрут поиска: `https://www.ultimate-guitar.com/search.php?search_type=title&value={query}`. Структура открытого ответа исследована, но [robots.txt](https://www.ultimate-guitar.com/robots.txt) запрещает `/search.php`, поэтому этот маршрут не допускается транспортом.
- Для импорта используется `store.page.data.tab` и `tab_view.wiki_tab.content` в `.js-store[data-content]`, разобранном как JSON после HTML-декодирования атрибута. Код сайта не исполняется. `[ch]...[/ch]`, `[tab]...[/tab]` превращаются в текст/структурированные аккорды; заголовки разделов сохраняются.
- Разрешены только доступные типы `Chords` и `Ukulele Chords`. `blocked`, отсутствующий текст, другой формат, некорректный JSON или challenge возвращают ошибку. Не используются мобильные API, токены, логин, подписка, cookies, печатные/скачиваемые версии или обход CAPTCHA.
- Политика импорта проверяется на [tabs.ultimate-guitar.com/robots.txt](https://tabs.ultimate-guitar.com/robots.txt), отдельно от политики `www`.

## Ручной разбор и точность

Пример полностью синтетического ввода:

```text
[Вступление]
| Am   G | D/F# | }x2

[Куплет 1]
  Am       G
  Пробный текст 🌍
[F♯m]Ещё одна [B♭]пробная строка

[Припев]
[C]Тестовый припев
[Припев]
```

Поддержаны аккорды над строкой с колонками, встроенные `[Am]`, Unicode `♯`/`♭`, slash-бас, табуляция (4 колонки), CRLF, NBSP, инструментальные строки, русские/украинские/английские заголовки и пустые повторные заголовки. Смещение считается в Unicode-кодовых точках, как `Array.from(text)` на frontend, включая emoji.

Инструментальная строка содержит пробелы для колонок якорей и полезные разделители/метки повторов; поддерживаемые названия аккордов не дублируются в её поле `text`. Числовые метки повторов сохраняются, а не разворачиваются бесконтрольно. Пустой повтор раздела разворачивается только после того, как установлено отсутствие написанного тела; новые объекты получают новые UUID. Все ограничения схемы продолжают действовать.

Используется существующий `backend.schema.normalize_chord`. Неподдерживаемые им обозначения (в текущей версии, например, power chord `E5`) сохраняются буквально с предупреждением; не подменяются другим аккордом и не дают невалидную палитру. Эта зависимость намеренна: расширение грамматики принадлежит владельцу схемы и автоматически станет доступно парсеру. Необычную ASCII-табулатуру, аппликатуры, произвольные обозначения и неоднозначные колонки следует проверить вручную. Строки, состоящие только из допустимых названий аккордов, интерпретируются как аккордные.

Тайминг, слова с временными метками и BPM из сайтов не выводятся. Для совместимости схемы задаются обычные начальные настройки `fontSize=24`, `bpm=120`, `beats=4`; это не измеренный темп. Язык выбирается эвристически из поддерживаемых схемой `ru`/`uk`/`en`. Результат предназначен для предпросмотра и редактирования пользователем.

## Ограничения транспорта

- Только HTTPS/443 и точные хосты `akkords.pro`, `mychords.net`, `chorder.ru`, их `www`-алиасы и `tabs.ultimate-guitar.com`. `www.ultimate-guitar.com` присутствует только в реестре политики/человеческих ссылок; произвольные страницы этого хоста не допускаются. Только конкретные шаблоны путей песен, построенный маршрут доступного поиска и `/robots.txt`.
- URL ограничен 2048 символами. Запрещены логин/пароль, произвольные порты, query-параметры импорта, управляющие символы, backslash, закодированные пути и dot-сегменты. Фрагмент страницы удаляется.
- Проверяются **все** DNS-адреса: один непубличный ответ запрещает весь запрос. Блокируются loopback, частные/служебные/документационные/многоадресные адреса и IPv6-переходы/отображения, способные скрыть IPv4. Подключение выполняется к уже проверенному числовому IP; повторного разрешения имени нет. TLS проверяет настоящий hostname и сертификат. Proxy-переменные окружения не используются.
- Не более 3 redirect-переходов. Каждый адрес проходит allowlist, проверку того же источника, применимую robots-политику и новую проверку DNS. Перенаправление на localhost, закрытую сеть, другой источник, HTTP или неподдерживаемую страницу запрещено до соединения.
- Общий deadline 15 секунд на получение robots-политики, DNS, TLS, заголовков, redirect и тела; DNS до 4 секунд, соединение/TLS до 4 секунд на попытку, чтение до 3 секунд без данных. Watchdog прерывает сам сокет и при медленной выдаче заголовков/тела. Не более 4 IP-попыток на соединение.
- Максимум 2 MiB тела страницы, 128 KiB robots-политики. Только HTML для песен/поиска. Запрашивается несжатый ответ; неожиданные сжатые ответы и другие типы отклоняются. Поддержаны UTF-8 и Windows-1251. Неполный/слишком большой/неподходящий ответ не становится результатом поиска.
- Максимум 4 одновременных сетевых запроса и 4 DNS-задачи без бесконечной очереди. На приложение — 20 некэшированных запросов поиска/импорта в минуту. Кэш поиска: максимум 64 ключа, TTL 5 минут, максимум 20 результатов на ключ; ошибки не кэшируются. Политики robots кэшируются на 10 минут для конечного списка хостов; отсутствие robots с HTTP 404 считается отсутствием запрета, остальные ошибки проверки блокируют запрос.
- HTML не выполняется и не отправляется в API. Пределы разбора: 50000 элементов/фрагментов, глубина 96, тело 2 MiB. Скрипты, стили, iframe, SVG и виджеты игнорируются. Не выполняются фоновые загрузки ресурсов страницы.
- Ручной ввод: до 120000 символов текста, 200 символов названия/исполнителя, до 768000 байт JSON до декодирования; ограничения строк/разделов/палитры/числа аккордов согласованы со схемой.

## Тесты

Все fixtures синтетические, без полных текстов реальных песен. HTTP/DNS в тестах заменены заглушками; реальные страницы проверялись отдельным запуском с выводом только метаданных/счётчиков и проверкой `Song.model_validate`.

```powershell
$env:PYTHONPATH = "backend/.deps;."
python -m pytest backend/tests/test_sources_parser.py backend/tests/test_sources_adapters.py backend/tests/test_sources_network.py backend/tests/test_sources_api.py -q -p no:cacheprovider
```

Windows sandbox может блокировать создание локальной пары сокетов `asyncio`, необходимой `TestClient`; в такой среде тесты запускаются с разрешёнными локальными сокетами. Это не причина отключать сетевую проверку адресов в приложении.
