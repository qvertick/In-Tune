# Разделение записи на вокал и аккомпанемент

Эта необязательная функция создаёт две дорожки из загруженной записи: вокал и
аккомпанемент. Обработка выполняется локально на процессоре, без отправки аудио в
интернет. Используется одна модель **htdemucs**. Исходная запись, текст, аккорды,
тайминг и установленная модель Whisper остаются без изменений.

Результаты сохраняются в FLAC: стерео, 44,1 кГц, 24 бита. При запуске приложения
ничего не скачивается. Если функция уже установлена, повторять установку не нужно.

## Как установить

Нужны Windows, 64-разрядный Python 3.12 и FFmpeg, доступный через PATH.
Откройте PowerShell в папке проекта:

~~~powershell
# Установить отдельную среду обработки и одну модель:
.\install-separation.ps1 -DownloadModel
~~~

Загрузка весов модели — **84 141 911 байт (80,24 МиБ)**. Среда PyTorch значительно
больше: проверенная загрузка пакета CPU для Windows/Python 3.12 — **619,4 МБ**,
плюс другие зависимости. После распаковки они занимают больше места на диске.

Для установки только среды, без скачивания модели, запустите:

~~~powershell
.\install-separation.ps1
~~~

Установщик создаёт папку **.venv-separation**. Он не меняет основную среду
приложения, backend/.deps, установленный Whisper или run.py. Пакеты CUDA и другие
модели не устанавливаются. Переменные PYTHONPATH/PYTHONHOME временно убираются из
окружения установочных процессов и затем восстанавливаются.

Перед явной загрузкой установщик показывает размер, запрашивает актуальный
Content-Length или сообщает, что размер неизвестен. Загрузка ограничена точным
числом байтов; затем проверяется полный SHA-256. Маркер успешной установки
появляется только после проверки. Повторный запуск использует уже скачанный
исправный файл. Если существующий файл повреждён, переместите его в другую папку
и повторите установку: повреждённые веса автоматически не заменяются.

## Подключение к приложению: для разработчика

Основное приложение подключает готовую фабрику маршрутов:

~~~python
from .separation import separation_router

app.include_router(separation_router(
    lambda: app.state.store,
    lambda: app.state.jobs,
))
~~~

Getters обращаются к app.state после начала lifespan. Модуль не создаёт свою
очередь, Store, Jobs или дополнительный рабочий поток. Используется существующий
последовательный FIFO-обработчик Jobs с видом задачи **separation**. Распознавание,
аккорды и тайминг сохраняют прежние процессоры и результаты Song.

| Маршрут | Ответ |
| --- | --- |
| GET /api/separation/status | available, modelInstalled, command, modelSize, note; только лёгкие проверки установки и FFmpeg, без загрузки модели |
| POST /api/songs/{id}/separation | 202 и существующая сводка Jobs с kind: separation |
| GET /api/songs/{id}/stems | ready: false и необязательное error, либо ready: true, vocalsUrl, accompanimentUrl, duration |
| GET /api/songs/{id}/stems/vocals?v=... | Локальный FLAC через FileResponse; поддерживает HTTP Range для перемотки |
| GET /api/songs/{id}/stems/accompaniment?v=... | То же для аккомпанемента |

Пример готового результата:

~~~json
{
  "ready": true,
  "vocalsUrl": "/api/songs/00000000-0000-0000-0000-000000000001/stems/vocals?v=0123456789abcdef0123456789abcdef",
  "accompanimentUrl": "/api/songs/00000000-0000-0000-0000-000000000001/stems/accompaniment?v=0123456789abcdef0123456789abcdef",
  "duration": 8.0
}
~~~

Нужно дождаться конечного состояния задачи, затем запросить /stems.
Для завершённого разделения **resultAvailable остаётся false**, а Jobs.result(id)
возвращает None: этот механизм предназначен для черновиков Song, не файлов.
Существующие /api/jobs/{id}/result и import-result отвечают 409. Фиктивный Song
или иной формат результата в SQLite не записывается.

Обе дорожки используют временную шкалу оригинала. FFmpeg учитывает задержку
декодирования MP3; тишина не обрезается. FLAC не добавляет задержку кодера, а
метаданные содержат offsetSeconds: 0. Настройки смещения исходного документа
остаются ответственностью проигрывателя и не переписываются.

URL содержит поколение результата. Устаревшее поколение отвечает 404.
FileResponse использует Cache-Control: no-store. Для последовательных запросов
FLAC/Range проверка SHA-256 источника кэшируется по разрешённому пути и признакам
stat: устройство, inode, размер, mtime_ns, ctime_ns. Кэш содержит до 32 небольших
записей, без аудио, и действует не более двух секунд. Замена файла обычным
загрузчиком меняет путь сразу. Если внешний редактор специально восстановит все
доступные временные метки, устаревшее чтение ограничено двумя секундами.
GET /stems, проверка повторного использования и проверка перед публикацией
всегда вычисляют полный SHA-256 и обходят этот кэш.

Неизвестная песня: 404. Нет локального аудио или недопустимый путь: 422.
Не установлена необязательная обработка: 503 с командой установки.
Переполнена очередь: 429. Уже активная задача той же песни возвращается
существующей очередью, даже если её вид другой: вызывающая сторона проверяет kind.
Если в приложении включены старые сеансы Following, маршрут учитывает их
блокировку и отвечает 409 при активном сеансе; он сам их не включает.

## Файлы, память и отмена

Расположение файлов:

* Среда: .venv-separation; маркер успешного импорта — separation-runtime.json.
* Установленные версии: .venv-separation/installed-requirements.txt.
* Веса и маркер установки: models/separation/htdemucs.
* Дорожки: data/stems/{songId}/{generation}/vocals.flac и accompaniment.flac.
* Готовность: data/stems/{songId}/metadata.json — единственный указатель результата.
* Временные данные: папки .tmp-* внутри папки дорожек песни.

Метаданные содержат версию рецепта, модель, поколение, сохранённое имя оригинала,
число байтов и SHA-256 источника, длительность, частоту, нулевое смещение и размеры
обоих FLAC. Указатель сначала пишется во временный файл, сбрасывается через
flush/fsync и атомарно заменяется только после готовности обеих дорожек.

Готовый результат используется повторно только для точного имени файла,
отпечатка содержимого и рецепта обработки. Замена или удаление оригинала
делает старые результаты недействительными. Перед публикацией проверка
выполняется ещё раз. Предыдущее поколение удаляется после успешной публикации,
если Windows позволяет; открытый файл не приводит к удалению оригинала.

При ошибке или отмене временные данные убираются. При запуске Jobs, уже после
захвата своей исключительной блокировки каталога данных, убирает оставшиеся
временные папки. Прерванная работа получает failed с понятным предложением
повторить запуск; ранее запрошенная отмена сохраняется как cancelled. /stems
может показать ошибку последнего разделения. Если отмена выигрывает последнюю
транзакцию Jobs сразу после публикации, новое поколение и его указатель
удаляются. Отмена поздней задачи повторного использования не удаляет ранее
готовый корректный результат.

Ограничение записи — 10 минут. FFmpeg декодирует на диск не более 601 секунды,
тайм-аут декодирования — 120 секунд. После декодирования проверяется фактическая
длительность. В памяти модели находится максимум **4 секунды** с перекрытием
**1 секунда**; выход записывается последовательно в два FLAC. Принудительное
дополнение HTDemucs до обучающей длины отключено. Ансамблей, случайных сдвигов,
параллельных пакетов и полных тензоров длинной записи нет.

Аккомпанемент вычисляется как смесь минус вокал, без независимой нормализации
громкости. PCM24 ограничивает только выходящие за диапазон отсчёты. Короткие окна
уменьшают потребность в памяти, но могут снижать качество разделения.

Перед инференсом захватывается общая блокировка providers._lock. Под ней
очищается кэш Whisper и вызывается follow_provider.unload_model(). Блокировка
удерживается до выхода процесса разделения; другой каталог данных не сможет
одновременно загрузить речевую модель. Сами установленные модели остаются на диске.

В Windows виртуальная среда использует запускающий процесс-переадресатор.
Чтобы отмена завершала именно обработку, backend запускает базовый интерпретатор
напрямую с -I -S и добавляет только каталог пакетов отдельной среды.
PYTHONPATH/PYTHONHOME удаляются из окружения дочерних процессов. FFmpeg и
инференс запускаются отдельно; процесс модели не запускает своих потомков FFmpeg.

Команды передаются списками аргументов с shell=False. Проверка отмены и остановки
сервера выполняется каждые 50 мс: завершается только собственный процесс,
ожидание до 3 секунд, при необходимости kill, затем обязательное ожидание выхода
перед удалением временных данных. Предельное время инференса — 6 часов;
отмена работает независимо от него. Через API нельзя передать путь, сетевой
источник, команду, имя модели или имя выходного файла.

## Будущая видеокарта

Сейчас установлена только CPU-версия. Для будущей NVIDIA GPU замените torch
только в отдельной среде сборкой CUDA из [официального установщика PyTorch](https://pytorch.org/get-started/locally/),
повторите проверку --check-runtime и задайте IN_TUNE_SEPARATION_DEVICE=cuda
перед запуском сервера. Вес модели остаётся тем же. Автоматической установки GPU
или скрытого переключения на CPU нет. Этот вариант здесь не проверялся.

Для управляемой отдельно среды администратор может задать
IN_TUNE_SEPARATION_PYTHON — путь к её Python. В корне среды должен находиться
маркер, созданный успешной проверкой --check-runtime.

## Как повторить тесты

Обычные тесты не скачивают и не запускают настоящую модель:

~~~powershell
$env:PYTHONPATH='backend/.deps'
python -m pytest backend/tests/test_separation.py backend/tests/test_separation_real.py -q --basetemp .tmp/sep-tests
~~~

Проверяются отсутствие зависимостей, отмена и завершение настоящего дочернего
процесса, освобождение очереди, восстановление после перезапуска, удаление
временных файлов, неизменность оригинала, замена источника и повторное
использование, атомарная публикация, безопасные пути, HTTP Range, кэш проверки
источника, число отсчётов при склейке окон, ошибки размера/контрольной суммы
и освобождение общей блокировки моделей. Процессные тесты используют явно
обозначенный заменитель инференса, не настоящие музыкальные результаты.
Короткий --basetemp обходит ограничения длинных путей Windows/песочницы.

После явной установки отдельно можно запустить реальные проверки:

~~~powershell
$env:PYTHONPATH='backend/.deps'
$env:IN_TUNE_TEST_REAL_SEPARATION='1'
python -m pytest backend/tests/test_separation_real.py -q -s --basetemp .tmp/sep-real
Remove-Item Env:IN_TUNE_TEST_REAL_SEPARATION
~~~

Они создают восемь секунд синтетического звука во временном Store, запускают
реальный процессор Jobs и отдельно проверяют отмену установленного процесса.
Папка данных приложения и пользовательские песни не читаются. Без переменной
IN_TUNE_TEST_REAL_SEPARATION эти проверки пропускаются. Полный отчёт обычных
проверок разделения, Jobs, тайминга и аккордов: **132 passed, 2 skipped**.
После добавления проверки кэша Range отдельно повторены тесты разделения:
**23 passed, 2 skipped**. Пропущенные по умолчанию реальные проверки обработки
и отмены были отдельно запущены вручную; обе прошли успешно.

Полный запуск backend остановлен на существующем тесте test_crud_export_import:
он ожидает, что Whisper не установлен, хотя пользователь уже установил Whisper
tiny. Установка Whisper сохранена; чужой тест и основная схема не изменялись.
